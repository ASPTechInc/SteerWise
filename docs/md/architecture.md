## Principles

- **Layered organisation**: Code is grouped by role (config, models, providers, services, simulation, screens, widgets) to keep clean separations between modules.
- **Logic apart from widgets**: The simulation rules (`DrivingGame`) and question filtering (`filterQuestions`) are plain Dart, so they are unit tested without building widgets.
- **Theming**: Supports light, dark and system themes, persisted with `shared_preferences`.
- **Offline first**: Questions, instructions and the simulation are bundled with the app and need no network connection.
- **No third-party artwork**: The splash animation and simulation are drawn in code; the icon and logo are original. Content from elsewhere (the DVSA questions) is credited under its own licence in `REUSE.toml` and in the app.
- **Scalability**: Supports addition of new features (e.g. map view, session recording, progress tracking).

## App Flow

1. `main.dart` loads `SharedPreferences`, then provides `ThemeProvider` and the shared `TtsService`.
2. `SteerWiseApp` (`app.dart`) builds the `MaterialApp` and shows the `SplashScreen`.
3. After the splash animation, `BottomNav` (`navigation/persistent_nav.dart`) shows three tabs:
   - **Home** - camera preview, the current voice instruction, the embedded driving simulation and the Next Instruction, Auto Mode and Get Feedback buttons.
   - **Show Me/Tell Me** - questions loaded from `assets/data/show_me_tell_me_questions.json`.
   - **Settings** - theme choice (system, light or dark).
4. `BottomNav` keeps every tab alive but wraps each in a `TickerMode` that is only enabled for the selected tab, so the Home tab's simulation and camera pause while another tab is showing.
5. Each tab opens the `AppSidebar` drawer. Its pages (Help, Licence, Privacy policy, About) open on the root navigator through the named routes; Feedback opens the GitHub issue form.

## State Management

SteerWise uses a lightweight approach:

- [`provider`](https://pub.dev/packages/provider) for app-wide state (`ThemeProvider`) and services (`TtsService`)
- `setState` for screen-level state (instructions, questions, mini map settings)
- `DrivingGame` is a `ChangeNotifier`; the painters repaint from it directly, so the widget tree does not rebuild every frame

---

## Theme & Preferences

- `AppTheme` holds theme data (light & dark), using the palette in `AppColours`
- `CustomTileColours` extends `ThemeData` with the Show/Tell tile colours
- `ThemeProvider` uses `shared_preferences` to persist the user's theme setting; preferences load before the first frame, so there is no flash of the wrong theme
- Default theme respects device settings, and users can return to it in Settings

---

## Voice Instructions

- Instruction text is defined in `AppConstants.instructions`
- Spoken by `TtsService`, one shared [`flutter_tts`](https://pub.dev/packages/flutter_tts) engine configured once with an `en-GB` voice. A new phrase interrupts the previous one, so screens never talk over each other
- Auto Mode moves to the next instruction every 8 seconds

---

## Routing

- Centralised in `lib/src/config/routes.dart` (`AppRoutes`)
- Named routes are used for navigation outside the bottom navigation bar
- Each tab has its own navigator, so push named routes on the root navigator:
  ```dart
  Navigator.of(context, rootNavigator: true).pushNamed(AppRoutes.help);
  ```

---

## Driving Simulation

- `DrivingGame` (`lib/src/simulation/`) holds the rules. Positions are relative to the simulation area (x from -1 to 1, y from 0 to 1), so it behaves the same at any size
- A `Ticker` in `DrivingSimulationScreen` advances the game once per frame, scaled by elapsed time and capped at 50 ms per step
- One traffic light cycles green, amber and red; oncoming cars wait at the stop line unless it is green
- The player snaps between the left and right lanes. Driving into an oncoming car ends the run, and Retry starts a new one
